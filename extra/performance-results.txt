AppKit reported the same 120 Hz internal / 60 Hz external rates in this setup.
Review rejected this optimization: maximumFramesPerSecond is an integer maximum,
not an equivalent display-mode refresh-rate query (including fractional rates).
The installed, reviewed implementation retains the original winit query. These
native-query numbers describe a rejected experiment, not a delivered speedup.
Apple API reference: https://developer.apple.com/documentation/appkit/nsscreen/maximumframespersecond

Correctness (after review):
- cargo test --locked --workspace: PASS (293 tests, including 90 app, 134 terminal unit,
  45 terminal reference tests; two opt-in benchmarks excluded from normal run).
- Raw grid writes, resize, alternate screens, wrapped/empty/anchored/greedy regex
  cases compare against the uncached matcher.
- Review fixed forward regex iteration crossing a leading wide-character spacer:
  a match can overshoot the search end, which previously allowed wraparound and
  infinite repeated matches. The cache also retains the visible scan's early exit
  and keys the viewport stop line. Long wrapped CJK, greedy patterns and viewport
  changes with unchanged logical search bounds are covered by regressions.
- Immutable render snapshots survive subsequent combining-character writes.
- Default palette fast path checked across named/indexed/RGB, bold/dim/inverse.
- Final app OpenGL readback: 1040 × 696, zero different pixels versus baseline.
  Includes CJK, combining marks, emoji, OSC 8, colored underline, bold/italic,
  hidden/inverse text and TUI borders. Capture uses only isolated test processes.
- Final native PTY/status acceptance: PASS, 50000 changing and 50000 duplicate
  reports; final status delivered, two native-title updates during change storm.
- make app: PASS; bundle signed and verified before installation.
