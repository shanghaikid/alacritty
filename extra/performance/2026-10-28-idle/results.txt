Alacritty idle memory — 2026-10-28

Purpose
Bring idle footprint close to Ghostty 1.4.0 while preserving terminal semantics.
This continues the earlier locally installed optimized Alacritty, not upstream
Alacritty. The implementation remains an uncommitted working-tree change.

Implementation
- Inline compressed row descriptors (u32 offset/length) reference one shared
  compressed block and expansion cache for up to 16 rows. Row<Cell> is 32 bytes,
  CompactRow<Cell> is 16 bytes, Cell remains 24 bytes.
- Grapheme tails are encoded in the LZ4 stream instead of retained as per-cell
  style dictionary entries. Explicit empty extras, long tails, underline colors,
  hyperlinks, wrap/wide flags and immutable snapshots remain lossless.
- Idle maintenance keeps only 64 cached spare rows and replaces an oversized
  row-vector allocation; Darwin realloc/shrink_to had retained its physical pages.
  A completed idle pass asks the allocator to release unused pages even for an
  empty or cleared history. Maintenance remains activity-driven, not periodic.
- The first glyph atlas is 512 square; later atlases retain 1024. An oversized
  initial glyph falls back to the regular atlas. GLSL3 CPU/GPU instance buffers
  start at 1024 and grow on demand; maximum batch size remains 65536.
- Active uniform scalar packing and the existing PTY pipeline are preserved.
  Rows with arbitrary styles/grapheme extras can still remain dense while active.

Method and scope
Apple M1 Pro, macOS 15.7.9, arm64 native apps; 120x40 cells, Menlo 11, grapheme
mode enabled, equal line limits and unlimited Ghostty byte limit. Unique numbered
history lines prevent an identical-line-only comparison; the varied Unicode
corpus has 2048 deterministic rows, larger than the short grapheme cache.
Darwin physical footprint includes the main terminal process, not the benchmark
child. Empty, filled and cleared stages are measured after documented waits;
idle/clear waits are 3 seconds. The parent samples peaks every 10 ms, which is not
an instantaneous high-water guarantee. Each final memory case uses three pairs
with alternating order. No compilation or other native benchmark runs concurrently.

The final comparisons load the same test-only Cocoa library into both processes.
It suppresses activation and external keyboard/mouse input in the test windows;
windows remain normal, ordered behind existing windows. This is a background
comparison, not proof of equal foreground/occluded/hidden-tab behavior or GPU
energy. The library is not bundled with or enabled in the delivered application.
Foreground results and earlier launch-library results are retained separately,
not pooled. Native pixel and input-latency acceptance runs do not use this shim.

Tradeoffs and limits
Compressed history must decode for search/reflow and can temporarily expand
memory when read. Whole-block cache sharing reduces small allocations but expands
up to 16 rows on first access. Idle work later recompresses expanded blocks.
The style dictionary is bounded; unsupported high-style-entropy blocks retain
lossless dense storage. Active styled/complex-Unicode memory is not claimed to
match Ghostty. The matrices cover selected corpora on one desktop, not every
possible history, font, renderer, OS, or window configuration.

Rejected experiments and measurement corrections
CGLReclaimResources crashed an isolated diagnostic app and was not adopted.
GPU finish/swap limit, delayed allocator relief, opaque surface and vsync probes
showed no consistent gain and were not adopted. Some foreground runs received
unrelated keyboard input and were rejected. One background run also did, leading
to the input-isolating shim. Incomplete runs are never pooled into complete pairs.
The history microbenchmark was corrected after noticing Arc-shared cache warming
between operations: every cold search, viewport sweep and reflow now prepares its
own grid before timing. Earlier affected timings are explicitly supplemental.

Reproduction
Use a dedicated temporary CARGO_TARGET_DIR with an EXIT cleanup trap, preserving
any requested deliverable before cleanup. Never retain Rust build caches.
cargo test --locked --workspace
cargo check --locked -p alacritty_terminal --no-default-features
cargo clippy --locked --workspace --all-targets -- -D warnings --force-warn clippy::question_mark --force-warn clippy::useless_borrows_in_formatting
cargo run --locked --release -p alacritty_terminal --example history-performance -- 100000
clang -O2 -fobjc-arc -dynamiclib -framework AppKit extra/terminal-benchmark-background.m -o SHIM.dylib
codesign --force --sign - SHIM.dylib
For output-only comparisons set TERMINAL_BENCH_BACKGROUND_LIBRARY to absolute SHIM.dylib:
python3 extra/compare-terminal-resources.py --alacritty NEW --ghostty GHOSTTY --config-directory extra/performance/2026-10-28-idle --output OUT --pairs 3 --corpus CORPUS --history 100000
For ASCII omit --history to cover both 10k and 100k.
python3 extra/compare-terminal-performance.py --alacritty NEW --baseline OLD --output OUT --pairs 3 --mib 64 --samples 5 --workload cjk
Without the shim:
python3 extra/render-acceptance.py OLD NEW RENDER_OUT
python3 extra/frame-pacing-acceptance.py NEW CONFIG FRAMES_OUT

Cold reflow now shares block expansion on mutable access as well as reads,
avoiding one full decompression per row in the same block. The corrected
100k-row cold reflow drops from roughly 0.51–0.54 s to 0.21–0.23 s.

Remaining simple-text gap
The final CJK and ANSI samples are 9.55 and 10.55 MiB above Ghostty, while
ASCII, graphemes and varied Unicode are lower. This is comparable overall idle
footprint across the selected cases, not a claim of winning every workload.
A final isolated CJK profile reports 29.9 MiB in five IOSurface regions.
Setting surface volatile state was rejected as an optimization: Apple Silicon
logs that GLD_SET_SURFACE_VOLATILE_STATE is unsupported/not handled, and the
physical footprint and IOSurface allocation remain unchanged. This probe was
not adopted in production. Profiling measurements are diagnostic, not pooled
into the uninstrumented memory table.
