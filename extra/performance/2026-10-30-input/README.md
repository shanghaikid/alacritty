# Dense-text input rendering compared with Ghostty 1.4

On this macOS / Apple M1 Pro machine, multi-atlas batching reduced Alacritty's
measured input latency and active CPU below the Ghostty 1.4 reference in this
specific dense CJK/ASCII workload. This is not a claim of parity across all
terminal workloads or physical keyboard-to-display latency.

| Version | Median | P95 | CPU, one core | Physical footprint |
| --- | ---: | ---: | ---: | ---: |
| Alacritty before multi-atlas batching | 9.42 ms | 14.51 ms | 16.41% | 106.44 MiB |
| Alacritty after multi-atlas batching | 4.17 ms | 9.51 ms | 7.67% | 68.42 MiB |
| Ghostty 1.4.0 | 14.65 ms | 21.08 ms | 12.89% | 73.30 MiB |

Latency statistics pool 300 samples per version. CPU and footprint are medians
of three process runs. Individual JSON files include binary hashes; matching
CSV files retain the latency samples. Runs were sequential, in these orders:
Ghostty/before/after, after/before/Ghostty, Ghostty/after/before. No compilation
was running during these recorded measurements. Earlier diagnostic runs and
failed probe setup attempts are excluded.

## Change and source comparison

The `before` binary already contains the earlier buffer-orphaning fix. The
original input-lag binary is therefore not the baseline in this table.

Ghostty's local checkout is tagged `v1.4.0`. Its `src/renderer/generic.zig`
maintains multiple frame states, uploads cell buffers, and draws foreground
text with grayscale and color atlases in one instanced draw.
`src/renderer/Metal.zig` selects three frame states. The renderer thread and
Metal buffers avoid making the UI thread synchronously overwrite in-flight
text batches.

Alacritty's OpenGL renderer still split a batch whenever the next glyph used
a different atlas. Mixed ASCII/CJK pages repeatedly alternated those textures,
causing many small uploads and draw calls. The new GLSL3 batch accepts four
atlas textures with a per-instance selector. It retains cell order, flushes
when a fifth distinct atlas is needed or the instance limit is reached, and
restores texture unit zero for glyph uploads. Every sampler has a complete
texture binding, including unused slots. Buffer orphaning remains in place.
The GLES2 shader keeps its existing single-texture path.

This does not add Ghostty's Metal backend, separate render thread, growing
shared atlases, or triple-buffered frame architecture to Alacritty. Those
remain architectural differences, rather than requirements demonstrated by
this workload.

## Measurement and reproduction

Use `extra/compare-terminal-input.py` with `extra/terminal-input-probe.m`.
Both apps use Menlo 11, 140x35 cells, zero padding, and the same 600-character
CJK working set interleaved with ASCII. A child-local timer sends up to one
synthetic key every 50 ms and waits for its rendered black/white pixel marker
before sending another. Test windows do not take keyboard focus; no global
input or screen capture is used. Dimensions and all 100 acknowledgments are
required for every successful run.

OpenGL latency ends at GPU pixel readback before drawable flush. Ghostty's
Metal latency ends when its completed IOSurface is submitted to the layer,
which also includes completion dispatch to the main thread. These are useful
pipeline response measurements, but their endpoints are not identical and
neither includes physical display scanout. Keys are generated by a main-thread
timer, so time that timer spends blocked before event generation is excluded;
this is not a measurement of queued physical keystrokes under main-thread load.
The synchronous OpenGL readback
and IOSurface read lock also introduce different probe overheads. CPU numbers
include this instrumentation, exclude the Python driver, and cover the active
input interval. Footprint is sampled immediately before the terminal exits;
it is not long-term idle memory or large-scrollback memory.

The official Ghostty hardened signature suppresses DYLD instrumentation. A
complete temporary app copy was ad-hoc signed for this test; the installed
Ghostty app was not modified. An explicit probe-load marker prevents treating
an uninstrumented run as valid. Binary hashes reflect the test signatures.

Example:

```sh
PYTHONDONTWRITEBYTECODE=1 python3 extra/compare-terminal-input.py \
  --terminal alacritty --binary /path/to/alacritty \
  --label after-1 --output /tmp/input-comparison
```

Use `--terminal ghostty` and an instrumentable temporary Ghostty app binary
for the reference. Repeat with unique labels, swapping execution order.

## Verification

- Release build and four renderer tests passed, including interleaved atlas
  slot reuse, capacity exhaustion, and reuse after batch clearing.
- Standard framebuffer comparison: zero differing pixels.
- A separate stress comparison prewarmed 8,400 CJK glyphs over multiple frames,
  then interleaved glyphs from throughout that working set with ASCII, styles,
  combining characters and emoji: zero differing pixels.
- Final frame pacing check: 59.94 FPS; dense-input P95 5.60 ms with the
  existing frame probe and SF Mono profile. This is separate from the paired
  Menlo comparison above.
- Rust compilation used task-owned temporary target directories, removed on
  success and failure. No shared target directory or registry cache was cleaned
  by the task's cleanup procedure.

## Pre-push review

The GLES2 shared fragment-shader branch now expands sampling directly to the
original `texture2D` expression. This avoids adding an unqualified floating
point function return type to an ESSL 1.00 shader with no default float
precision. Native forced GLES2 dual-source testing on this Mac is blocked by
the pre-existing unsupported `GL_EXT_blend_func_extended` extension; no GLES2
runtime pass is claimed. The GLSL3 rendering path is unchanged by this fix.

The input tool now requires a separate successful child completion marker and
rejects a child error even when all 100 pixel acknowledgments and a zero
terminal exit code were recorded. It also removes the compiled probe on
signing or startup failures. Four failure-handling tests cover these cases.
The paired measurements above predate this extra completion check; the
original samples and metadata are preserved rather than relabeled as new runs.

Final review validation:

- Workspace release tests: 363 passed, 5 intentionally ignored.
- `alacritty_terminal --no-default-features`: 179 passed, including integration
  and documentation tests.
- Four input-probe failure-handling tests passed.

- Preprocessing the GLES2 shader produces the same tokens as the branch base
