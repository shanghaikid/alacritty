Alacritty performance shortfalls — 2026-10-28

Purpose
Reduce active history memory and 64 KiB burst acknowledgment delay relative to
the earlier optimized Alacritty delivered in target/performance-20261028.
This is a follow-up to extra/performance/2026-10-28/results.txt, not a comparison
with unmodified upstream Alacritty. Source remains a working-tree change.

Implementation
- Parser demand wakes the macOS PTY gather thread when its ready queue empties.
  Pending output is published immediately; queued bulk work can still be batched.
- Uniform scalar rows use four bytes per cell plus one shared row style, with
  Unicode scalar values and wrap/wide-cell flags preserved. Plain ASCII/CJK writes
  can update this representation directly, including recycled rows and wrapping.
- Other rows retain normal Cell storage. Complex edits materialize dense cells;
  immutable readers cache a lossless expansion. Existing idle LZ4 compression
  remains available for both forms. Recent/visible history is excluded from the
  archival scan, and grapheme rows skip futile scalar-packing attempts.
- Dense mutable indexing stays inline; expansion runs in a cold helper.
- Growing a cleared row marks the old columns occupied, preserving the uniform
  suffix invariant when new columns have a different background. Regression
  coverage compares both ASCII and CJK bulk writes with scalar behavior.

Final binary methodology
Apple M1 Pro, macOS 15.7.9, native arm64 .app bundles for both Alacritty versions.
Three alternating pairs per comparator, three 8 MiB samples per workload/process,
120x40 cells, Menlo 11, 10k history, grapheme mode enabled. Results below are the
median of the three process medians, in MiB/s. PTY timing ends at a cursor-position
reply, so it includes draining and parsing but excludes GPU/display presentation.
Memory uses three alternating pairs per comparator, 100k unique numbered lines
of 118 cells, Darwin physical footprint. Active is sampled after acknowledgment;
the parent also samples process footprint every 10 ms. Sampled peak is not a
guaranteed instantaneous high-water mark. Idle/clear samples follow 3-second waits.
No compilation or another native test runs concurrently with measurements.

Tradeoffs and limits
Active plain-text history and burst delays improve substantially. Some output
categories still have a throughput cost: the final paired medians include about
3% lower mixed Unicode, 6% lower wrapped ASCII and 8% lower ANSI/CJK versus the
previous optimized version. Earlier five-pair runs varied in magnitude/direction
for some categories; all raw measurements are retained rather than claiming
every workload improved. Empty/idle memory remains above Ghostty.
The scalar encoding does not cover arbitrary per-cell styles, hyperlinks or
grapheme extras: these retain dense storage until eligible idle compression.
Reading packed history expands cached cells; cold search/reflow therefore costs
CPU and temporary memory compared with dense-only history. Idle LZ4 compression
also has this cost, including in the previous version. Tests do not establish
latency on every desktop, GPU energy, hidden-tab behavior, or Linux/Windows parity.
Desktop timings fluctuate; smaller percentage differences should not be treated
as universal rankings or a statistically established advantage.

Earlier measurements and failed attempts
Five-pair throughput and three-pair 10k/100k memory measurements before the final
row-growth correctness fix are preserved as *-before-resize-fix.json. Their
binary differs from the final app, so they are not silently pooled into the final
tables. One earlier Ghostty batch was aborted because unrelated keyboard bytes
entered a probe; throughput-ghostty-aborted.json preserves its completed pairs,
excluded from the aggregates. An offline validation attempt could not resolve
uncached registry metadata; normal locked validation subsequently passed.
Earlier implementation experiments are retained in /private/tmp/alacritty-shortfalls.
